# OrcaSlicer — K2

OrcaSlicer is the recommended slicer for the K2 — in particular with [KAMP-K2](../helper-script/klipper-adaptive-meshing-and-purging-k2.md), which is developed and tested with OrcaSlicer. Using Creality's own slicer instead: see [Creality Print](creality-print.md).

Download: :material-github: [GitHub Releases](https://github.com/SoftFever/OrcaSlicer/releases/latest)

---

## Printer Profile

Select **Creality → Creality K2** with your nozzle size (0.2 / 0.4 / 0.6 / 0.8 mm). The K2 base profile is **Creality K2** — not K2 Plus (350 mm) or K2 Pro (300 mm), whose larger bed sends moves outside the K2's travel range, and not the smaller K2 SE. If you build a printer profile yourself, use the values below.

| Setting | K2 value |
|---|---|
| Build volume | 260 × 260 × 260 mm |
| Kinematics | CoreXY |
| Max speed | 600 mm/s |
| Max acceleration | 20,000 mm/s² |
| Max nozzle / bed temperature | 300 °C / 100 °C |
| Chamber heater | **None** — leave chamber temperature at 0 / off |

### Adaptive bed mesh limits

**Printer Settings → Basic information → Adaptive bed mesh**: set **Bed mesh min / max** to the `mesh_min` / `mesh_max` values of `[bed_mesh]` in your `printer.cfg`. On the K2 the maximum is typically **255, 255**. (The helper script changes a stock `mesh_min: 5,5` to `20,20`.)

## Machine G-codes

In OrcaSlicer, edit your printer preset and go to the **Machine G-code** tab.

### Machine start G-code — Creality original (without KAMP-K2)

OrcaSlicer's **Creality K2** printer profile already contains Creality's start G-code — keep it. It is taken from Creality Print 7.0.1 and is simpler than the current Creality Print profile (no CFS flush sequence, purge line along the left and front edge):

```gcode
; HEADER_BLOCK_START
; generated by Creality_Print V7.0.1.4212 on [year]-[month]-[day] at [hour]:[minute]:[second]
; total layer number: [total_layer_count]
; HEADER_BLOCK_END
; SET PRINT AREA MIN AND MAX COORDINATES TO ENABLE ADAPTIVE PROBING
; MINX = {first_layer_print_min[0]}
; MINY = {first_layer_print_min[1]}
; MAXX = {first_layer_print_max[0]}
; MAXY = {first_layer_print_max[1]}
M140 S0
M104 S0
START_PRINT EXTRUDER_TEMP=[nozzle_temperature_initial_layer] BED_TEMP=[bed_temperature_initial_layer_single]
T[initial_no_support_extruder]
M109 S[nozzle_temperature_initial_layer]
M204 S2000
G1 Z3 F600
M83
G1 Y150 F12000
G1 X0 F12000
G1 Z0.2 F600
G1 X0 Y150 F6000
G1 X0 Y0 E15 F6000
G1 X150 Y0 E15 F6000
G92 E0
G1 Z1 F600
```

The comment lines at the top only write information into the G-code file; they do nothing on the printer.

What each line does: [KAMP-K2 → Creality's original K2 start G-code](../helper-script/klipper-adaptive-meshing-and-purging-k2.md#crealitys-original-k2-start-g-code).

### Machine start G-code — with KAMP-K2

If you installed [KAMP-K2](../helper-script/klipper-adaptive-meshing-and-purging-k2.md) (option 6), **replace** the whole start G-code with OrcaSlicer's K2 original, with the fixed purge line swapped for `LINE_PURGE` (the comment header can stay or go):

```gcode
M140 S0
M104 S0
START_PRINT EXTRUDER_TEMP=[nozzle_temperature_initial_layer] BED_TEMP=[bed_temperature_initial_layer_single]
T[initial_no_support_extruder]
M109 S[nozzle_temperature_initial_layer]
M204 S2000
G1 Z3 F600
M83
LINE_PURGE
```

- **Print Settings → Others → G-code output → Exclude objects** must be enabled — KAMP reads the object outlines from it. OrcaSlicer's Creality K2 presets have it on.
- Optional: `SET_PRINT_STATS_INFO TOTAL_LAYER=[total_layer_count]` as the first line for the layer count in Fluidd / Mainsail (see *Layer change G-code* below); `MESH=0` on the `START_PRINT` line skips the mesh for one print.

What changed compared to the original and why, what happens at print start and which console messages to expect: [KAMP-K2 → Start G-code](../helper-script/klipper-adaptive-meshing-and-purging-k2.md#start-g-code-with-kamp-k2).

!!! warning "One command per line — never split a command"
    The blocks above have **several lines, one complete command per line**. What must not happen is a single command being split over several lines: if your template has line breaks between `START_PRINT` and its parameters (for example, pasted from an older guide or edited by hand), the sliced file contains `BED_TEMP=60` and `EXTRUDER_TEMP=220` as separate lines. Klipper then sees them as unrecognized standalone commands and logs `Unknown command` (key61) errors for each one. Keep `START_PRINT EXTRUDER_TEMP=... BED_TEMP=...` together on one line and re-slice.

!!! note "No CHAMBER_TEMP on the K2"
    K2 Plus profiles pass `CHAMBER_TEMP=[chamber_temperature]` to `START_PRINT`. The K2 has no chamber heater, so it is left out here. See [Chamber Temperature](../improvements/chamber-temperature-k2.md).

**Machine end G-code:**
```gcode
END_PRINT
```

With [Auto Power Off](../helper-script/auto-power-off-k2.md) installed but not armed for every print, add `ACTIVATE_POWER_OFF` after `END_PRINT` in a profile you use for long or overnight prints.

**Before layer change G-code:**
```gcode
;BEFORE_LAYER_CHANGE
;[layer_z]
G92 E0
```

**Layer change G-code:**
```gcode
SET_PRINT_STATS_INFO CURRENT_LAYER={layer_num + 1}
;AFTER_LAYER_CHANGE
;[layer_z]
```

**Time lapse G-code** (if Moonraker Timelapse is installed):
```gcode
TIMELAPSE_TAKE_FRAME
```

**Change filament G-code** (if M600 Support is installed):
```gcode
M600
```

## Multi-Material Setup (K2 Combo with CFS)

For the K2 Combo, configure OrcaSlicer as a multi-material printer:

- Set the number of extruders to match your loaded CFS slots (up to 16 with four CFS units)
- The slicer's `T0`–`T15` tool change commands are translated to CFS slot addresses by the stock `box.cfg` macros
- Set flush/purge volume to match your `box.cfg` settings
- Purging during tool changes happens at the CFS purge chute (`extrude_pos_x/y` in `box.cfg`) — not as a line on the bed

See [CFS — Color Filament System](../helper-script/cfs-k2.md) for the full tool-change sequence.

## Upload G-code Files to Printer

- Click the **Connection** icon in OrcaSlicer
- Enter your printer's IP address:
    - For **Fluidd**: `http://<printer-ip>:4408/`
    - For **Mainsail**: `http://<printer-ip>:4409/`
- Click **Connect** — you can now upload and start prints directly from the slicer
